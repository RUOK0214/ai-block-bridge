# AI Block Bridge 2 — 파일 기반 자동화 애드온

AI Block Bridge 2는 **외부 프로그램이 요청 파일을 넣으면 마인크래프트에서 블록 배치·안정화 점검·회로 테스트를 실행하고 결과 파일을 돌려주는 선택 설치 애드온**입니다.

AI가 회로를 설계하고, 게임에서 시험한 결과를 읽고, 수정한 회로를 다시 제출하는 작업에 사용할 수 있습니다. 애드온 자체에는 AI 모델, AI API 호출, 네트워크 서버, MCP 서버가 포함되어 있지 않습니다. 일반 프로그램으로도 같은 요청을 제출할 수 있습니다.

## 기본 모드와의 차이

| 구성 | 역할 |
|---|---|
| AI Block Bridge 기본 모드 | 구조·타임라인 텍스트화, 편집창, 수동 붙여넣기, 안정화 점검, 자동 테스트 |
| AI Block Bridge 2 애드온 | 폴더의 요청 JSON을 읽어 배치·점검·테스트를 순서대로 실행하고 결과 JSON 저장 |
| 외부 AI 도구 또는 연결 프로그램 | 요청 작성, 파일 제출, 결과 읽기, 다음 수정안 결정 |

텍스트 파일을 직접 AI에게 전달하는 용도라면 기본 모드만 설치하면 됩니다.

## 설치

- Minecraft Java **26.2**, Java **25**, Fabric Loader **0.19.5 이상**, 해당 Minecraft 버전용 Fabric API가 필요합니다.
- [릴리스 페이지](https://github.com/RUOK0214/ai-block-bridge/releases/latest)에서 기본 모드와 애드온을 받습니다.
- 0.2.2 기준 설치 파일은 `ai-block-bridge-0.2.2.jar`와 `ai-block-bridge-2-0.2.2.jar`입니다. 0.2.2 애드온은 기본 모드 **0.2.2 이상**이 필요합니다. 기존 버전 JAR는 교체합니다.
- 싱글플레이는 게임의 `mods` 폴더에 설치하고 치트를 허용합니다.
- 전용 서버에서는 실제 월드가 실행되는 서버에 기본 모드와 애드온을 설치합니다. 파일 제출 프로그램도 **서버의 폴더**를 대상으로 해야 합니다. 기본 모드의 클라이언트 UI를 사용할 때는 클라이언트에도 기본 모드를 설치합니다.
- 애드온 명령어에는 **OP 레벨 4** 권한이 필요합니다.

## 시작과 중지

1. 작업할 월드를 열고, 요청에 사용할 영역의 청크를 불러옵니다.
2. `/abb2 watch on`을 실행합니다.
3. 표시된 월드 이름을 확인하고 **30초 안에** `/abb2 watch confirm`을 실행합니다.
4. `/abb2 status`로 감시 상태와 실제 `in` 경로를 확인합니다.
5. 해당 `in` 폴더에 요청 JSON을 제출하고 `out`에서 결과를 읽습니다.
6. 마치면 `/abb2 watch off`를 실행합니다.

감시는 서버 세션 시작 시 꺼져 있습니다. 싱글플레이 월드를 다시 열거나 서버를 재시작하면 다시 켜야 합니다. 서버 틱으로 작업하므로 게임/서버가 실행 중이어야 하며, 싱글플레이 일시정지 상태에서는 진행이 멈출 수 있습니다.

`watch off`는 진행 중 작업을 취소하고 애드온이 적용한 속도 설정을 해제합니다. **이미 수행한 블록 변경은 되돌리지 않습니다.**

## 폴더 위치와 역할

게임 또는 서버 실행 폴더 아래에 `ai-block-bridge-2`가 만들어집니다. 기본 Windows 런처를 사용하는 경우의 예시는 다음과 같습니다.

```text
%APPDATA%\.minecraft\ai-block-bridge-2
```

별도 런처 프로필·인스턴스·서버에서는 경로가 달라질 수 있습니다. `/abb2 status`에 나오는 경로를 기준으로 연결하세요. 이 폴더는 월드별 보관함이 아니므로 다른 월드에서 감시를 켜기 전에 대기 중인 요청을 확인하세요.

| 폴더 | 내용 | 누가 사용하는가 |
|---|---|---|
| `in` | 아직 처리하지 않은 요청 `.json` | 외부 프로그램이 제출 |
| `processing` | 애드온이 가져가 처리 중인 원본 요청 | 애드온이 이동·관리 |
| `out` | `<요청 id>.json` 결과 | 애드온이 작성, 외부 프로그램이 읽음 |
| `done` | 결과 저장 후 보관된 원본 요청 | 애드온이 이동·관리 |

애드온은 요청을 **한 번에 하나씩**, 파일 이름의 사전순으로 처리합니다. `in`에서 `processing`으로 먼저 옮긴 뒤 실행하고, 결과를 `out`에 저장한 뒤 원본을 `done`으로 옮깁니다.

**`done`은 처리 완료 보관함이며, 테스트 합격을 뜻하지 않습니다.** `out`의 `status`와 `test` 내용을 함께 읽어야 합니다.

## 요청 JSON

`in`에는 일반 배치 스크립트 TXT 대신 **스크립트를 포함한 UTF-8 JSON**을 넣습니다. 아래는 월드 좌표 `(0,64,0)`에 돌 한 개를 놓고 확인하는 예시입니다. 실제로 작업할 좌표로 바꾸세요.

```json
{
  "id": "attempt-0001",
  "dimension": "minecraft:overworld",
  "region": [0, 64, 0, 0, 64, 0],
  "clear": false,
  "sprint": 0,
  "tickRate": 0,
  "script": "0 0 0 | minecraft:stone",
  "test": "@case stone exists\nexpect 0 0 0 | minecraft:stone"
}
```

파일 이름도 `attempt-0001.json`처럼 `id`와 맞추는 것을 권장합니다. JSON 해석 전에 실패하면 파일 이름을 기준으로 오류 응답이 만들어질 수 있기 때문입니다.

| 필드 | 필수 / 기본값 | 의미 |
|---|---|---|
| `id` | 필수 | 영문 대소문자·숫자·점·밑줄·하이픈으로 1~64자. 요청마다 새 ID 사용 |
| `dimension` | `minecraft:overworld` | 작업할 차원 |
| `region` | 필수 | 두 모서리의 **월드 좌표** `[x1,y1,z1,x2,y2,z2]`. 양 끝 블록 포함 |
| `script` | 빈 문자열 | 배치 스크립트 문자열. 기본 형식과 코드화 팔레트 형식 지원 |
| `test` | 빈 문자열 | `@case`, `set`, `wait`, `expect` 테스트 대본 문자열 |
| `clear` | **true** | 배치 전에 요청 영역을 비울지 여부 |
| `sprint` | 0 | 가속 실행을 요청할 틱 수. 0~20,000, 0은 요청하지 않음 |
| `tickRate` | 0 | 서버 틱 속도 설정. 0 초과~1,000, 0은 변경하지 않음 |

`script`와 `test` 중 하나 이상은 비어 있지 않아야 합니다. 두 필드는 파일 경로가 아니라 **파일 내용 자체**를 담습니다. 줄바꿈과 따옴표는 JSON 직렬화기로 이스케이프하세요.

작업 범위는 **요청 JSON의 `region`**으로 결정됩니다. 기본 모드 UI의 현재 선택 영역과 무관합니다. 스크립트와 테스트의 좌표는 이 영역의 X/Y/Z 최솟값을 원점으로 하는 상대좌표입니다. 예시의 `0 0 0`은 월드의 `0 64 0`을 뜻합니다. 파일의 `# size`나 `# origin` 주석으로 작업 영역을 변경할 수 없습니다.

현재 제한은 요청 파일 **16,000,000바이트**, 영역 **1,048,576블록**, 배치 스크립트 **2,000,000자**, 테스트 대본 **200,000자**입니다. 테스트는 최대 256사례·4,096단계, `wait` 합계 6,000틱입니다. 읽히지 않은 청크·월드 경계 밖·높이 밖 작업은 거부됩니다.

### 기존 블록 유지와 영역 비우기

**애드온의 JSON `clear` 기본값은 true입니다.** 기본 모드 수동 붙여넣기의 기본 keep과 다릅니다.

| JSON `clear` | 스크립트 지시자 | 결과 |
|---|---|---|
| false | 없음 또는 `# unlisted: keep` | 적지 않은 좌표 유지 |
| false | `# unlisted: clear` | 영역 전체 교체 |
| true 또는 생략 | 어떤 유효한 지시자든 | 영역 전체 교체 |

JSON 또는 스크립트 중 하나라도 비우기를 요청하면 비웁니다. `# unlisted: keep`은 JSON `clear:true`를 취소하지 않습니다. 잘못된 값과 중복 지시자는 비우기 전에 거부됩니다.

기존 회로를 **테스트만** 하려면 `script`를 생략하고 반드시 `clear:false`를 지정하세요.

```json
{
  "id": "check-0001",
  "dimension": "minecraft:overworld",
  "region": [0, 64, 0, 0, 64, 0],
  "clear": false,
  "test": "@case existing stone\nexpect 0 0 0 | minecraft:stone"
}
```

테스트에 `set`이 있으면 그 단계는 실제 블록 상태를 변경합니다.

### 파일 제출 예시 — Python

같은 PC에서 실행하는 프로그램은 다음처럼 제출할 수 있습니다. Python 3가 필요하며, `root`는 실제 게임/서버 경로에 맞추세요. 감시를 먼저 켜서 폴더가 생성된 상태에서 실행합니다.

```python
import json
import os
import uuid
from pathlib import Path

root = Path(os.environ["APPDATA"]) / ".minecraft" / "ai-block-bridge-2"
request_id = "attempt-" + uuid.uuid4().hex
request = {
    "id": request_id,
    "region": [0, 64, 0, 0, 64, 0],
    "clear": False,
    "script": "0 0 0 | minecraft:stone",
    "test": "@case stone exists\nexpect 0 0 0 | minecraft:stone",
}
temporary = root / "in" / (request_id + ".json.tmp")
destination = root / "in" / (request_id + ".json")
temporary.write_text(json.dumps(request, ensure_ascii=False), encoding="utf-8")
temporary.rename(destination)
print("결과 파일:", root / "out" / (request_id + ".json"))
```

완성된 파일만 읽히도록 같은 폴더에 `.json.tmp`로 저장한 뒤 `.json`으로 이름을 바꿉니다. 애드온도 결과를 임시 파일에 쓴 다음 최종 `.json`으로 바꿉니다. 외부 프로그램은 `out/<id>.json`이 나타나면 읽으면 됩니다.

요청 ID와 파일 이름은 매번 새로 만드세요. 기존 ID를 재사용하면 이전 결과와 혼동하거나 기존 결과가 덮어써질 수 있습니다. 하나의 결과를 확인한 다음 다음 요청을 제출하면 수정 작업을 추적하기 쉽습니다.

## 결과 읽기

정상적으로 실행을 마치면 `out/<id>.json`에 다음 필드가 기록됩니다.

| 필드 | 의미 |
|---|---|
| `id` | 요청 ID |
| `status` | `done`: 실행 절차 완료 / `error`: 요청 처리 오류 |
| `placed` | 배치 스크립트에 적힌 좌표 수. 비운 블록 수는 포함하지 않음 |
| `ticks` | 엔진이 처리한 서버 틱 수 |
| `ms` | 측정된 실행 시간(밀리초) |
| `settle` | 요청한 블록 상태와 안정화 점검 시점의 실제 상태 차이. 배치 스크립트가 없으면 빈 문자열 |
| `test` | 테스트 사례별 PASS/FAIL과 기대값·실제값. 테스트가 없으면 빈 문자열 |

오류 응답에는 `id`, `status: "error"`, `error` 설명만 들어갑니다.

**`status: "done"`이어도 회로 테스트에 FAIL이 있을 수 있습니다.** AI나 외부 프로그램은 `test`의 합격·실패 수와 각 사례를 읽어야 합니다. 안정화 점검은 업데이트 후 10틱 시점의 관찰이며 모든 회로가 완전히 안정되었다는 보장은 아닙니다. 긴 동작은 테스트 대본의 `wait`로 기다린 뒤 검사하세요.

`tickRate`는 작업 영역뿐 아니라 **서버 전체**의 속도를 바꿉니다. 종료·취소 시 이전 틱 속도로 복원하며, 요청한 sprint가 실행 중이면 중지합니다. 가속이 지원되지 않거나 적용되지 않는 환경에서는 서버 로그를 확인하세요.

## AI와 연결하기

애드온을 설치했다고 웹 채팅의 AI가 PC 폴더에 자동으로 접근하는 것은 아닙니다. 연결 방식은 AI가 실행되는 위치에 따라 달라집니다.

| 사용 방식 | 필요한 연결 |
|---|---|
| 사용자가 직접 전달 | AI가 만든 JSON을 사용자가 `in`에 저장하고, 결과 JSON을 AI에 첨부 |
| 로컬에서 실행되는 AI 코딩 도구 | 게임/서버 폴더에 대한 파일 읽기·쓰기 권한을 부여해 직접 제출·결과 확인 |
| PC 밖에서 실행되는 채팅형 AI | PC에서 실행하는 연결 프로그램과, AI 서비스가 호출할 수 있는 도구 연결 필요 |

별도 연결 프로그램을 만든다면 다음 세 기능을 제공하면 됩니다.

- **작업 제출:** 요청 JSON을 검사하고 `in`에 저장한 뒤 요청 ID 반환.
- **진행 확인:** 해당 요청이 `in`, `processing`, `done` 중 어디에 있는지 확인.
- **결과 읽기:** 해당 ID의 `out` JSON 반환.

MCP를 지원하는 AI 도구에는 이 기능을 MCP 도구로 제공할 수 있습니다. 로컬 AI는 로컬 연결을, 원격 AI는 해당 서비스가 지원하는 인증된 원격 연결이나 터널을 사용해야 합니다. MCP 서버를 실행하는 것만으로 채팅에 등록되지는 않으며, AI 서비스 쪽 연결 설정도 필요합니다.

**이 저장소의 0.2.2 배포물에는 연결 프로그램·MCP 서버·터널이 포함되어 있지 않습니다.** 연결 프로그램은 위의 폴더 입출력 규약을 이용해 별도로 구현합니다. 폴더 접근 범위는 이 애드온 폴더로 제한하고, `processing`과 `done`의 이동은 애드온에 맡기면 됩니다.

연결 후 작업 흐름은 “AI가 요청 제출 → 애드온이 게임에서 실행 → AI가 결과 읽기 → 수정안을 새 ID로 제출”입니다. 상시 무인 반복 실행 여부는 외부 AI 프로그램의 실행 방식에 달려 있습니다.

## 중단·오류 복구

- **자동 되돌리기나 복구 파일은 없습니다.** 애드온 실행은 기본 모드의 ‘붙여넣기 취소’ 기록을 만들지 않습니다. 별도 테스트 월드나 월드 복사본에서 사용하세요.
- 잘못된 배치·테스트 구문과 블록 상태는 비우기 전에 검사합니다. 실행 도중 오류나 중단이 발생하면 이미 변경된 블록은 남을 수 있습니다.
- 서버 중단 뒤 `processing`에 남은 요청은 **자동 재실행하지 않습니다.** 월드와 `out`을 확인한 다음, 재실행이 필요할 때만 새 ID·새 파일로 제출하세요.
- 결과 저장이나 `done` 이동이 실패하면 재시도하며 다음 요청을 시작하지 않습니다. `out`에 결과가 있어도 원본 보관이 아직 끝나지 않았을 수 있습니다.
- `in`에서 요청을 가져오는 단계가 실패하면 감시가 비활성화될 수 있습니다. 파일 충돌·쓰기 권한과 서버 로그를 확인한 뒤 감시를 다시 켜세요.
- 응답이 늦다고 같은 요청을 즉시 재제출하지 마세요. 감시 상태, 서버 일시정지, `processing`, 기존 결과, 서버 로그를 먼저 확인하세요.
